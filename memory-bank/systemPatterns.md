# System Patterns

## Architecture Overview
- **Engine**: Namespaced runtime (Engine::), modules (Core, Memory, RenderPipeline, PhysicsManager, etc.). Static lib or DLL; ModuleManager loads IModule implementations.
- **Client**: Depends on Engine; game-specific components, resources, render tasks.
- **Build**: Sharpmake generates solutions and FastBuild BFF; projects add Intermediate/HeaderParser/<ProjectName>/HeaderGenerated as include/source for generated files.

## Build Pipeline (evaluated)

### Where things come from
- **Solution file**: Generated by **GenerateSolution.bat**. Not the source of truth; the source of truth is the set of **build.cs** files.
- **Projects**: Each **build.cs** (Engine/Source/Runtime/**/**.build.cs, Client, Launch, Monolith, etc.) defines a project; Sharpmake emits one vcxproj (and FastBuild targets) per such project. So **if any build.cs is modified** (new project, dependency, path, compiler option), the solution and project files **must be re-generated** by running GenerateSolution.bat (or by building Launch/Monolith, whose prebuild runs it).

### Pipeline order when building
1. **Solution generation** (once per build.cs change): GenerateSolution.bat builds Sharpmake, optionally generates header-parser.vcxproj via CMake, then runs Sharpmake with EngineMain, ClientMain, KolibriMain → Kolibri.sln (root), Intermediate/ProjectFiles (Engine.sln, Client.sln, vcxprojs, .bff).
2. **Prebuild (each build)**: Launch and Monolith prebuild (Utils.AddSolutionPrebuildSteps): `cargo build --release` (balius), then GenerateSolution.bat so project files are up to date. Then for each C++ project: **balius** runs (header modification detection): copies headers to Intermediate/HeaderParser/<ProjectName>, git diff; if headers changed, writes **target file** (list of header paths) and invokes **header-parser** with that file. **Header-parser** reads the target file, parses each header, and **generates required definitions and implementations** using **file macros** (bodygeneration_macro.h) and postGenerated (to .generated.cpp). Output: .generated.h and .generated.cpp under Intermediate/HeaderParser/<ProjectName>/HeaderGenerated.
3. **Compilation**: **FastBuild** (FBuild.exe) does the actual compile/link; its BFF and targets are **aligned by Sharpmake** (generated in step 1). Include paths point to HeaderGenerated so `#include "X.generated.h"` resolves.

### Header generation (detail)
- **Balius**: Header modification detection; passes headers to header-parser by writing the **target file** (one path per line) and running header-parser.exe. Hash skip when no .h/.hpp change; per-project git at Intermediate/HeaderParser/<ProjectName>; copies headers, ensures &lt;Conf&gt;.dep; if changes, commit, write target file, run header-parser. Hash in Intermediate/HeaderParser/Hash.
- **Header-parser**: Parses headers from the target file (from balius); generates .generated.h and .generated.cpp using **bodygeneration_macro.h** (GENERATE_BODY_HEAD, GENERATE_BODY_STATIC, polymorphic_type_hash, etc.) and postGenerated (s_dependencies_, cloneImpl, BOOST, resource static_assert) into .generated.cpp. IModule base emitted as Engine::IModule.

## Key Technical Decisions
- **RTTI-free reflection**: type_hash, polymorphic_type_hash, HashTypeT, safe_cast (CoreType.h). Types opt in via GENERATE_BODY.
- **Core independence**: TypeLibrary and Core headers do not include/forward non-Core runtime types. IGraphicAPI uses Abstracts::Resource*; D3D12 etc. cast at boundary.
- **Module pattern**: IModule (InitializeImpl/ShutdownImpl, GetDependencies); ModuleManager holds and initializes.

## Component Relationships
- Core depends on Memory. Render/Physics/Sound modules depend on Core. Client depends on many engine modules. Balius and header-parser are build-time only.
